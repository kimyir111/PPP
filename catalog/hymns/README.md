# 찬송가 piano scores

One hundred public-domain hymn tunes from the [Open Hymnal Project](http://openhymnal.org/) (ABC SATB settings, 2014.06), reduced to two-staff piano MusicXML.

Korean titles are the names these hymns are sung under in 찬송가 use. This is not the official 새찬송가 engraving, and it does not include hymnal lyrics.

Each `index.json` row names the MusicXML file and a YouTube piano-performance watch id for Practice.

Rebuild from a local Open Hymnal ABC tree with:

```
set OPENHYMNAL_ABC=path\to\abc
node catalog/hymns/build.js
```

## MX-2 (2026-09): key signature, tie stops, in-bar accidentals

`abc-to-musicxml.js` used to write `<alter>`/`<accidental>` only for a note with an explicit ABC
accidental mark; every other note (the vast majority) got no `<alter>` at all, so the app played
it natural regardless of the key signature or an earlier accidental in the same bar. It also wrote
`<tie type="start"/>` but never the matching `<tie type="stop"/>`. Fixed: the converter now applies
the key signature's default alteration, carries an explicit accidental for the rest of its bar
(same pitch letter+octave, same staff, across every voice on that staff), and writes matching tie
stops (`tests/bench/pppbench/known_defects.py` classes `key_signature_playback`,
`bar_accidental_not_carried`, `tie_without_stop`).

The 100 committed `.musicxml` files were **not** regenerated by re-running `build.js`: the ABC
source tree the `OPENHYMNAL_ABC` env var used to point to was a temp directory from an earlier
session and no longer exists on disk, and it was never committed. Re-running the (now fixed)
converter against re-fetched ABC would risk pulling in text that no longer matches what these
files were built from. Instead, the shipped MusicXML was patched directly with a one-off script
(not committed) implementing the same algorithm off each file's own existing pitch/octave/duration/
measure/staff data, which the three defects never touched. Nothing about durations, rests, steps,
octaves, measures or bar structure changed — only `<alter>`, `<accidental>` and `<tie>`/
`<notations><tied>` on the affected notes. If the ABC source tree is ever recovered, prefer
rebuilding with `build.js` over hand-patching again.

Independent review found the converter fix had a latent ordering bug (a tie crossing a bar
boundary into a pitch that differs from the key signature's default never fed back into that bar's
carried-accidental state for other voices on the same staff) — dormant in these 100 files (verified:
`catalog/hymns/tools/test-key-signature.js`), but real for any future rebuild. Fixed with an
additional forward-propagation pass in `abc-to-musicxml.js`.

Since the one-off patch script itself is unrecoverable and was never an audit trail,
`catalog/hymns/tools/check-accidentals.py` independently re-derives, from the shipped MusicXML
alone (trusting neither `abc-to-musicxml.js` nor the lost patch script), what every note's
`<alter>` should be from the key signature, in-bar carry and tie chains, and fails if any of the
100 files disagree. Run it after any manual edit to a hymn file:

```
python catalog/hymns/tools/check-accidentals.py
```
